# Sponsor Developer Feedback Inbox

Every role records reproducible sponsor bugs and concrete feature requests here.
Create one Markdown file per report named
`YYYYMMDD-sponsor-bug-or-feature-short-title.md`; do not edit another role's
report. Include:

- sponsor and product/API;
- `bug` or `feature request`;
- concise title and impact;
- reproduction steps or concrete use case;
- expected and actual behavior;
- evidence paths, response/request IDs, versions, and region when relevant;
- workaround, if any;
- author role and status: `candidate`, `captain-reviewed`, or `submitted`.

Never include credentials or private media URLs. The Integration Captain reviews
for duplicates and evidence before submission with `./give_developer_feedback.sh`.
